- 手机检查使用浏览器内 390 × 844 视口，未在实体手机上测试。
- 业务流转的完整正反向检查以本地自动化测试为主，未对全部按钮组合进行穷举人工测试。
- 未对真实比赛日程进行网络查询，初始比赛均为明确标注的示例。

## 尚未处理的既有问题

本轮以去重和结构整理为主，以下审计问题仍需后续处理，不能用测试全部通过替代这些结论：

- 两个标签页几乎同时保存时，仍缺少版本冲突检测，后一次整份快照写入可能覆盖另一页的更新。
- 借用进入“待发放”后，归还期限已过时缺少取消或重新安排的恢复入口。
- 默认只有一位指导老师时，该老师自己的申请没有可审批人。
- 比赛流程节点到时、整体比赛状态不变时，“下一节点”可能需要手动刷新。
- 模块历史借用详情与借用列表的可见范围不一致，需明确哪些历史字段可向所有成员公开。
- API 模式需区分“提交失败”和“已提交但刷新失败”，并与后端约定幂等提交；目前没有真实后端可验证。
