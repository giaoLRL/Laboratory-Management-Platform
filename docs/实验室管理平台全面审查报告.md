# 具身智能实验室管理平台 · 全面审查报告

> 审查日期：2026-09-25
> 审查范围：后端 `lab-platform`（Django 6.x 纯 JSON API）+ 前端 `lab-platform-web`（无依赖原生 JS SPA）+ 业务逻辑与产品完整性
> 审查方式：架构级代码走查 + 交叉验证（关键高危项已逐行核实）

---

## 总体评价

架构骨架扎实：前后端分离干净、RBAC 权限模型成熟（46+ 权限点全覆盖）、借用/任务并发锁实现严谨、响应/鉴权/媒体路径规范统一、迁移链完整。

但存在 **2 个确定性上线 Bug、1 个密钥泄露、1 个部署即失效的隐性故障**，以及一批安全纵深、数据一致性、业务流程闭环问题。

按优先级分四层：🟥 高危（必须立即修复）→ 🟧 中危（安全纵深与可靠性）→ 🟨 业务/产品层 → 🟩 规范性问题。

## 🟥 高危：必须立即修复

### 1. 比赛创建必然 500（确定性 Bug）

`apps/competitions/api.py:106` 取 `data["registrationEnd"]`，但 `_validate` 写入的键是 snake_case `registration_end`（L88）。KeyError → 500；且创建动作在 KeyError 前已落库**且无事务包裹**，用户看到报错重试会生成重复比赛。

- 修复：改为 `data["registration_end"]`，`Competition.objects.create` 包进 `transaction.atomic`。

### 2. DeepSeek API Key 明文硬编码进仓库

`scripts/deploy_server.sh:54`：`-e LAB_LLM_API_KEY=sk-e734158e9b3f43f89e4c5605912a0d19` 明文写在部署脚本里。拿到仓库即拿到密钥（可调用付费 LLM API）。

- 修复：改为从部署环境/密钥文件读取，**立即吊销该 key 重新签发**。

### 3. SECRET_KEY 每次部署重新生成 → 邮件提醒部署即静默失效

`scripts/deploy_server.sh:46` 每次 `head -c 16 /dev/urandom` 换新 key。而 SMTP 密码用 `signing.dumps` 加密存储（`apps/email/models.py:5-7`），`_decrypt` 对 `BadSignature` 静默返回空串（L11-17）→ **每次部署后所有邮件规则全部失效**，且无任何报错，需人工重录密码。会话本身存服务端不受影响，所以此前一直未暴露。

- 修复：SECRET_KEY 首次生成后持久化（`.env`/volume），部署脚本"缺失才生成"。

### 4. settings 默认值反向安全

`lab_api/settings.py:16-17`：`SECRET_KEY` 默认已知字符串、`DEBUG` 默认 `'1'`。任何漏注入环境变量的部署 = 已知密钥 + 调试模式（堆栈泄漏、签名可伪造）。

- 修复：缺失即 `raise ImproperlyConfigured`，`LAB_DEBUG` 默认 `'0'`。

### 5. 前端存储型 XSS（2 处）

- `src/levels.js:67`：关卡地图 `title` 属性中 `l.description` 未经 `esc()` 拼入 HTML 属性，管理员可写入含 `"` 的描述逃逸属性注入 `<img onerror>`，**全员浏览关卡地图即触发**。
- `src/app.js:47/49`：面包屑与侧边栏的 NAV label 来自后端下发且直拼 innerHTML，superadmin 编辑的导航 label 可在每个登录用户 shell 执行。
- 修复：两处补 `esc()`。

### 6. API 令牌明文挂 window 全局

`src/sysmo.js:336-337`：`window._lastToken`。与上面两个 XSS 点叠加 = 窃取令牌。

- 修复：改为模块级 `let` 闭包变量，用完即置空。

## 🟧 中危：安全纵深与可靠性

### 安全

| 问题 | 位置 | 影响 |
|---|---|---|
| 写接口全豁免 CSRF，仅靠 SameSite=Lax 单层 | `apps/common/auth.py:11` | 防御纵深不足 |
| HTTPS 站点 Cookie 无 Secure 标志、无 HSTS、无 `SECURE_PROXY_SSL_HEADER`（nginx 已传 X-Forwarded-Proto） | `settings.py:110-114` | Cookie 在 HTTPS 上无 Secure |
| 登录无防爆破、无失败锁定；**未知用户名不落审计** | `accounts/api.py:54-82` | 针对不存在账号的爆破零痕迹 |
| 登录日志 IP 取 XFF 首值，客户端可伪造 | `accounts/api.py:41-44` | 审计数据可信度 |
| 弱口令策略过宽（`12345678a` 即通过）、无黑名单/相似校验；**管理员创建账号不强制首登改密**（仅重置才置位） | `accounts/api.py:17`、L328 | 弱口令长期可用 |
| `email_logs` 接口仅 IsAuthenticated，任何登录用户可读收件人/主题/SMTP 错误 | `email/api.py:89-96` | 隐私泄漏 |
| 权限矩阵维护（角色增删/授权/覆盖）**零审计日志** | `accounts/api.py` | 最敏感操作无痕 |

### 数据一致性 / 并发

- **workspace 增量版本失效**：Loan/Maintenance/Leave/Competition 的 `_ts` 用 `created`（`inventory/api.py:84`），审批/发放/归还/归档等**状态变更不改 created** → 持有旧快照的前端看不到审批结果。
  - 修复：为这些模型增加 `updated`（auto_now）字段并在 `_ts` 中使用。
- **并发竞态**：
  - 积分发放 exists+create 非原子，撞唯一约束 500；
  - 关卡 EXP 读-改-写竞态（`levels/api.py:45-48`），应改用 `F()` 原子累加；
  - `next_code` 全表扫描无锁（`common/ids.py:16-24`），并发创建同号 → 主键冲突 500；
  - 打卡每日唯一检查非原子，并发可产生同日两条。
- 小组成员调配两步 update 无事务（`accounts/api.py:756-762`），中途失败成员无组。

### 性能（2GB 机器 / 1 worker）

- 3 处 N+1：成员全量 `effective_roles()`（50 人 ≈ 100+ 查询，`workspace.py:18`）；任务列表未 select_related（每任务 4 次查询，`tasksapp/api.py:51`）；公告未预取（`notify/api.py:14/33`）。
- 任务详情日志 `text__icontains` 全表 LIKE 无索引（`tasksapp/api.py:441`）。
- CSV 导出全量装载无分页 + 每行一次用户查询（`accounts/api.py:383-409`）。
- 前端每次写操作全量重拉 workspace（两次串行请求，`core.js:171-175`）。

### 权限不一致

- `login_logs` 接口用 `is_staff` 而非权限点（`accounts/api.py:343`）：有权限点的自定义角色进得去页面、接口 403。
- 关卡审核人表（LevelReviewer）形同虚设：审核从不校验该表，任何持 `action:level.review` 者可审任意关卡（`levels/api.py:323-384`）。
- `action:points.manual` 是死权限点：矩阵里存在、后端无接口、前端无按钮。
- 通知可见性判断用 `profile.role in ('teacher','manager')` 硬编码，与全局 `can_manage` 漂移（`notify/api.py:47-53`）。

### 前端功能缺陷

- **写操作 401 不跳登录**：会话过期后所有操作静默弹错，只有 `/auth/me` 分支处理 401（`core.js:135-142`）。
- **打卡页搜索框/成员筛选完全失效**：渲染了控件但 `list` 不过滤（`checkins.js:19-38`）。
- **6 处前端硬编码 `me().role` 绕过 RBAC 权限点**（`core.js:277-320`），与 API.md「不要在前端二次推导权限」冲突，自定义角色行为错乱。
- 30 秒轮询触发**整页 render**（重建含侧边栏/顶栏的整个 shell，`features.js:913-923`），定时器永不清理。
- `invalidateProfile` 在同文件重复定义（`levels.js:310` 与 L391），后者静默覆盖前者——"顶层函数被覆盖"坑的同类。
- API.md 契约漂移 3 处：`/members/me/update` 漏 `number` 字段、`/members/:id/update` 漏 `email`、**checkins 模块在 API.md 完全缺失**。
- 公告"刷新"按钮未 await 就 render（`sysmo.js:274`），刷新无效。
- mock/生产双路径交错，演示密码明文出现在登录页 HTML。

## 🟨 业务/产品层：用户真实会遇到的问题

> 业务定位说明：**比赛模块为信息展示用途**（通知学生有哪些比赛与安排，报名/参赛由省里统一安排，不在系统内），因此"比赛报名闭环"不构成问题，不评估。

| # | 业务问题 | 现状与影响 |
|---|---|---|
| 1 | **逾期治理缺环** | 逾期任务不再提醒（`send_reminders.py` 只查 `due__gte=now`）；逾期成员**仍可发起新借用**；积分只加不减、无逾期惩罚。借用信用分与积分联动未落地 |
| 2 | **邮件覆盖面 + 语义错误** | "维修完成"邮件**发给自己**（`inventory/api.py:213-216`）；任务审核结果、公告发布、归还验收等高频事件无邮件规则；**ETL 未迁移 User.email 到 MemberProfile**，老用户收不到任何邮件 |
| 3 | **提醒 cron 未随部署安装** | `send_reminders.py`/`fetch_news.py` 依赖宿主机 cron，但 `deploy_server.sh` 无安装步骤——若服务器未手工配，全部提醒静默失效且无告警 |
| 4 | **请假无销假** | 已批准请假无法撤销、无到岗登记，考勤只靠前端按时间窗口推算 |
| 5 | **任务删除不受状态限制** | 已审核完成、已发积分的任务可直接删，积分流水悬空 |
| 6 | **停用成员不检查未完成任务** | 停用后任务负责人失联且看板无提示 |
| 7 | **CSV 导出覆盖不全** | 缺资产/请假/维修/积分/登录日志，借用导出无损坏信息（期末汇报要的资产台账反而没有） |
| 8 | **操作日志无结构化字段** | 只有文本+截断 256 字符，无法回答"某资产/某借用单的全部变更历史"（用 `icontains` 模糊匹配代替）；比赛/新闻/积分规则改动不写日志 |
| 9 | **checkins 半成品** | AGENTS.md 声称含"签退"，实际只有每日一次签到；积分规则 `checkin_streak` 定义了但从未发放 |
| 10 | **归还验收无二次确认** | 误点即改资产状态 + 发积分 |
| 11 | **智能体工具参数与后端契约不匹配** | `create_task` 的 `assignee` 传"姓名"必然失败（后端要 `m<id>`） |

## 🟩 规范性问题（低危）

- 借用单 `_ts` 隐私裁剪与外层 version 语义混用（粗粒度）。
- `inventory` 快照无意义 OR 全量查询 + 同一份数据查两次（`inventory/api.py:71/75`）。
- 多处低质代码：`accounts/api.py:493` 两分支相同；`tasksapp/api.py:327` f-string 写法绕弯；`inventory/api.py:275/278` 死代码赋值。
- 对象删除不清理磁盘文件 → media 目录孤儿文件累积（`tasksapp/api.py:464`）。
- 权限点声明与后端强制不一致：`action:task.attachment` 声明非 frontend_only 但实际用 `_can_edit_task`；`action:points.manual` 无后端实现。
- `members_active` 布尔解析：表单编码传 `"false"` 字符串将得 `True`（`accounts/api.py:435`）。
- 通知/公告可见性两套判断逻辑漂移（`notify/api.py`）。
- 智能体 `create_task` 工具 assignee 参数与后端契约不匹配（`agent/service.py:35-40`）。
- 上传体积限制链不一致：nginx 50m < Django 60MB < 关卡声称 100MB。
- 生产无 LOGGING 配置，错误仅 gunicorn stderr。
- 前端 `animations.js` MutationObserver 常驻监听整个 `#content` 子树，与 30s 整页重建叠加。
- agent 页 500ms 硬编码延迟预加载，首屏空态闪烁。
- 任务评分表单默认分值与视觉不一致（默认 3 分但 5 星均无高亮）。
- 大量内联样式与魔法数（PAGE_SIZE 按视口分档等）。
- 权限矩阵/导航配置页离开后 `_permMeta` 缓存不失效。
- 前端 `audit()` 本地写日志与后端审计双写歧义。
- `applySnapshot` 字段合并会删除后端漏发字段。

## ✅ 核查通过项（避免误报）

- 原生 SQL 仅一次性 ETL 内固定字符串，无注入面。
- 除 CSV/媒体响应外全部接口统一走 `ok()/fail()`。
- `loans_create/issue/receive` 均用 `transaction.atomic + select_for_update`，借用库存扣减本身无竞态。
- Token 只存 SHA-256 哈希、明文仅创建时返回一次。
- 媒体路径穿越防护（`os.path.commonpath` 校验）正确，生产走 X-Accel-Redirect 直发。
- 迁移链完整、抽查 app 模型与迁移字段一致。
- 前端事件委托无泄漏；URL 注入面基本闭合；敏感数据未落库持久化。
- "单窗口不滚动"约束成立（`overflow:hidden` + 分页 + 标签页）。
- 成员详情页聚合数据全部真实打通，他人数据走隐私裁剪，无越权。

## 建议处理路线

1. **今日可修（确定性 Bug + 安全）**：比赛 500、API Key 吊销+外置、SECRET_KEY 持久化、settings 默认值、前端两处 XSS + window 令牌、写操作 401 跳登录、打卡搜索失效。
2. **本周（可靠性与一致性）**：`_ts` 改用状态变更时间戳（迁移加 updated 字段）、并发三处（积分/EXP/next_code）、N+1 批量预取、email_logs 加权限、前端 role 硬编码收敛到 `can()`。
3. **按 P0 路线补业务闭环**：逾期任务提醒 + 逾期停借、销假、任务删除状态限制、维修完成邮件改收件人、cron 接入部署脚本、ETL 邮箱回填、创建账号强制首登改密 + 登录防爆破。
4. **需要产品决策的**：`action:points.manual` 是否实现手动调分；关卡指定审核人是否强制；checkins 是否做签退；mock 分支是否从生产代码剥离。
