# 可视化座位界面设计（实验室俯视图小游戏）

> 目标：把「座位」做成一张活的实验室俯视图——打卡后你的小人出现在座位上，签退后消失；可以挪位、冒气泡、设状态，让谁在实验室、在干什么一眼可见。
> 风格延续「专业、克制」：俯视图为工业舱体网格风（藏蓝中性底色 + 几何小人），不做花哨动效，与品牌统一。

## 一、核心需求（原需求保留）

1. 可视化座位界面，像网页小游戏。**每人打卡后，其座位上出现一个小人。**
2. 座位界面是整个实验室的**俯视图**，按方格划分；点击空格可让**自己的小人移动**过去，**不能改变别人的位置**。
3. **打卡下班（签退）后小人消失。**
4. 增加互动性：小人可以**发一条消息**，在座位上变成一个**气泡**显示文字。
5. 每个人可**设置状态 + 文字**（例如「调试中 · 在跑电机闭环」）；**点击别的小人**弹出悬浮文字 + 状态（他正在干嘛）。
6. 每个人的 **SVG 人物形象可自定义**。

## 二、核心规则定义

| 规则 | 定义 |
|---|---|
| **在席状态** | `今日已打卡 且 未签退`（跨天/次日自动视为离席）。**小人 = 在席**，由打卡数据派生，不另设开关。 |
| **座位占用** | 每个**格子同时最多 1 人**；被占用的格子不可再移动入内，也不可移动他人的小人。 |
| **挪位** | 只能移动**自己的小人**到**空格子**（含他人座位上的空格？否决——保留座位归属感，`Seat.default_member` 归属座位原则上只允许本人/无人时占用，默认开放任意空格即可）。 |
| **空位保留** | 本人小人移走后，原位立即释放为空。不设残留占位。 |
| **签退** | 当天签退后小人消失，再次出现需重新打卡。 |
| **气泡** | 发消息后在其格子上方显示气泡，**N 秒后自动消失**（默认 15s，服务端强制过期清理），点击可提前关闭。 |
| **状态** | 每人在席期间的「状态 + 文字」，**持续到签退或手动修改**；只读公开。 |

## 三、数据模型草图

```
SeatLayout（布局，管理端可配）
  id, name, rows, cols, cells(JSON: 每格的类型矩阵,如工位/桌子/通道/门/储物/障碍),
  scale_hint(前端缩放), created/updated

Seat（座位格子）
  id, layout_id, label(座位号,如 B-03), row, col,
  kind(workstation|table|aisle|door|storage|block),
  default_member(默认归属成员,可空), status_ok(是否可用/维护中)

CheckInRecord（增强，复用打卡模块）
  现有: user, photo, latitude, longitude, created
  +signout_at(DateTimeField, null=未签退)   ← 迁移新增

SeatPresence（当前占位，冗余查询优化，可选）
  id, member_id, seat_id, from_checkin_id, reached_at
  —— 若为便于统计先不加，直接用 今日打卡未签退 × 最近一次挪位 聚集；挪位不落库的话，
     占用席位就始终 = default_member 的格子，故必须落 SeatPresence 记录「现在坐哪」。

（合并意见：占用来源 = today_checkin 未签退；seat = SeatPresence.latest）
  ▲ 下表按「落 SeatPresence」设计，避免挪位信息丢失。

SeatMessage（气泡）
  id, layout_id, member_id, text(≤50字), created, expires_at

SeatStatus（状态）
  id, member_id, status_key(预设键|'custom'), text(≤30字), updated_at

MemberCharacter（形象，独立小表）
  member_id(OneToOne), parts_json(JSON: 肤色/发型/发色/衣着/配件/眼镜...), updated_at
```

> 为什么小人形象不直接存 SVG 文本：任意 SVG 粘贴=存储型 XSS 通道。改为**参数化部件 + 白名单**，后端只存 JSON 参数，前端用白名单部件拼接生成 SVG（详见前端设计）。

## 四、实时性方案（定稿：Channels + WebSocket）

> 约束：生产 **gunicorn 1 worker + 4 threads、2GB 内存**。Django 同步 worker 不能挂长连接（1 个 WS 客户端即占死唯一 worker），故长连接必须由 **ASGI 服务器（daphne）** 承载，与普通请求同一进程分发。

### 1. 决策记录（为什么选 WebSocket）

| 候选 | 结论 |
|---|---|
| 增强轮询 | 延迟 1~2s，游戏感不足，仅作断线兜底 |
| SSE 网关 | 效果与 WS 相同、改造小，但**单向**，无法承载后续双向交互 |
| **Channels + WebSocket（选定）** | 延迟 <100ms 与 SSE 持平；**双向通道一次建立**，为后续实时动态、协同类功能预留；全站实时化共用同一条 WS 通道 |

**选型代价（已评估可接受）**：daphne 替换 gunicorn 接管全部请求（部署脚本/Dockerfile 要改）；内存 +50~100MB（2GB 机器尚余量）；Django 6 + Channels 兼容性与同步视图在 ASGI 下的行为需在 P0 冒烟回归验证。若兼容性验证受阻，**回退到 SSE 网关方案**（前端共用 `applyEvent()`，零改动）。

### 2. 架构

```
浏览器 ── WS /ws/rt ──▶ daphne（ASGI, 8001）
   ▲                      ├─ channel_layer.group_send ▸ SeatConsumer（群发广播）
   │ REST 写操作           └─ 普通请求走 Django 视图（REST 与 WS 同端口同进程）
   └── POST /api/... ──────▶
```
- **部署形态**：daphne 替代 gunicorn 监听 8001，`ProtocolTypeRouter`：`http → django_asgi_app`，`websocket → AuthMiddlewareStack(URLRouter(/ws/rt → SeatConsumer))`。
- **channel layer**：单进程用 **InMemory** 即可（不引 Redis），`SeatConsumer` 订阅房间 `seat_events`。
- **鉴权**：Channels 的 `AuthMiddleware` 读会话 Cookie，与现有 `CsrfExemptSessionAuthentication` 同源兼容；Consumer 内校验 `scope['user']`，未登录直接关闭连接。
- **写操作不动**：挪位/气泡/状态/打卡/签退仍走 REST POST，处理成功后 `channel_layer.group_send` 广播（打包成 `seat_publish(event)` helper）。

### 3. 消息协议（WS 文本帧 JSON，增量 patch）

```json
{"type":"hello","seq":12345}                             // 连接基线序号
{"type":"presence","mid":"M003","seat":"B-07","offline":false}
{"type":"bubble","mid":"M003","text":"去借示波器","expiresIn":15000}
{"type":"status","mid":"M003","key":"debug","text":"跑电机闭环"}
{"type":"ping"}/{"type":"pong"}                          // 30s 心跳
```
- 客户端首帧发 `hello` 拿基线 `seq`，按序号合并跳过旧事件；状态漂移时全量拉一次 `/seats/presence` 校正。
- **重连降级**：WS 断开后前端自行实现退避重连（约 200 行 `rts.js`），重连期间切换 **2s 轮询**补拉；轮询与推送共用同一 `applyEvent()` 处理函数，平滑切换。

### 4. 部署改动点（P0 基础设施先行）

- `requirements.txt`：`+channels`、`+daphne`。
- `Dockerfile`/部署脚本：CMD 由 `gunicorn` 改为 `daphne -b 0.0.0.0 -p 8001 project.asgi:application`。
- `settings.py`：`ASGI_APPLICATION`、`INSTALLED_APPS + channels`、`CHANNEL_LAYERS = in-memory`。
- `asgi.py`：`ProtocolTypeRouter` + consumer 路由（见上）。
- **nginx**：`/api/`、`/media/` 不变；新增 `location /ws/`：`proxy_pass http://127.0.0.1:8001; proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; proxy_read_timeout 75s;`
- **冒烟回归**（P0 必做）：切换 daphne 后验证未登录 401、`/media/` 鉴权、REST 全接口正常、WS 握手并完成鉴权；任何异常即回退 gunicorn + 转 SSE 网关方案。

### 5. 游戏感前端层（原生 JS，`rts.js`）

- `requestAnimationFrame` 渲染循环 + CSS `transition`：小人挪位 300ms 平滑位移，非瞬间闪现。
- **乐观更新**：自己挪位本地立即动 + 并发事件；服务端拒绝（目标被占）→ 回滚 + 提示。
- WS 心跳/重连/降级轮询由 `rts.js` 统一封装，页面只感知 `onEvent()` 回调。

## 五、API 契约（统一 `ok()/fail()`，挂 `/api/` 前缀）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/checkins/{id}/signout` | 签退：置 `signout_at`，小人消失，记操作日志 |
| GET | `/seats/presence` | 今日在席清单（member + seat + 气泡 + 状态展开），可用于轻量轮询 |
| POST | `/seats/move` | 本人挪位：`{seatId}`，校验自己是本人、目标格为空、未签退 |
| POST | `/seats/message` | 发气泡：`{text}`，校验 ≤50 字、频率限制（如 60s 内 1 条） |
| POST | `/seats/status` | 设状态：`{statusKey, text}`，校验 text ≤30 字 |
| GET | `/seats/layouts` | 布局 + 全部座位（俯视图渲染数据源，管理/全员可见） |
| POST | `/seats/layouts` `/seats` | 布局与座位 CRUD（需 `action:seats.manage`） |
| POST | `/seats/character` | 保存本人形象参数 `{parts}`（白名单键校验） |

- 座位页数据优先来自 **workspace 快照**（`seats` / `presence` / `message` / `character` 数组），写操作走上述接口后前端本地更新 + 触发快照刷新。
- 契约同步三处：`API.md`、`core.js` 的 `applySnapshot`、`apps/common/workspace.py` 聚合。

## 六、前端页面设计

### 1. 页面 `#seats`（俯视图）
- 布局：左主体为**可缩放俯视图**（CSS Grid 铺格子，SVG 小人绝对定位），顶部工具条（刷新间隔显示 / 我的座位按钮 / 形象编辑器入口），可视一屏内完整呈现。
- 数据源：workspace 快照 + `presence` 轮询；渲染纯函数 + `data-action` 委托（沿用 features.js 注册式模式）。
- 格子视觉：工位=浅色内凹格、通道=深色地面、门/储物=图标格、障碍=禁行斜纹；**被占用格 = 小人 + 绿色呼吸边**（克制，无粒子动效）。

### 2. SVG 小人（参数化部件，白名单拼接）
- 部件槽：`skin / hair / hairColor / top(衣着) / bottom / prop(配件: 电脑/焊枪/书) / glasses`，每个槽位一套**内置 SVG 片段**（industrial 几何风格，非拟人卡通）。
- 生成：`characterSVG(parts) → <svg>`，前端拼装、`<defs>` 处理需唯一 id（复用 `_labMarkSeq` 模式）；**不接受上传任意 SVG**。
- 编辑器：弹窗内左预览右部件选择，实时拼装，保存走 `/seats/character`。

### 3. 交互
| 操作 | 行为 |
|---|---|
| 点击**自己的小人** | 打开「自己」面板：改状态/文字、发气泡、移动、编辑形象 |
| 点击**别人的小人** | 悬浮卡：名字、头像、状态+文字、当前座位号、「发条气话给他」 |
| 点击**空格** | 若是自己：确认后挪位（前端本地移动 + 调 `/seats/move` + 刷新）；他人不可点 |
| 点击**气泡** | 关闭该气泡（或 15s 自动消失） |
| 管理端 | 布局编辑模式：增删格子、改类型、设默认归属 |

### 4. 状态预设
- 后端下发状态键白名单：`在工位 / 调试中 / 开会 / 休息 / 实验室外(临时) / 自定义(文字)`，自定义时文字必填。
- 座位页默认显示「状态文字」，悬浮卡补全「状态 + 文字 + 座位号」。

## 七、权限与安全

- 新增权限点：`page:seats`（座位页入口）、`seats.move / seats.message / seats.status`（本人操作，全员默认有）、`seats.manage`（布局/座位 CRUD，仅管理角色），接入 RBAC 矩阵。
- **XSS**：SVG 一律参数化白名单拼接，禁止上传任意 SVG/HTML；气泡与状态文字全部 `esc()` 渲染。
- **防刷屏**：气泡频率限制（60s 1 条）、长度限制；签退后不可再发消息/挪位。
- **越权**：`/seats/move` 仅能且只能移动自己（后端以 `request.user` 为准，不信任前端传 memberId）。

## 八、与现有系统衔接

- **打卡**：复用 `checkins`，唯一改动是 `CheckInRecord` 加 `signout_at` + 新接口；`checkins.js` 打卡成功弹窗增加「顺便选座」入口。
- **workspace**：`apps/seats/api.py` 提供 `workspace_slice(profile, staff)`，追加 `seats / presence / messages / statuses / characters`，`_ts` 参与快照 version。
- **成员**：名字/头像/角色复用 `member`；悬浮卡显示 `Mxxxx` 短 ID 无需暴露主键。
- **通知（可选 P1）**：签到/签退/入座动作可写操作日志与实时动态（复用 notify），但座位页本身默认静默，不弹站内通知，避免打扰。
- **积分（暂不联动）**：打卡积分已存在，座位系统不改积分口径，保持克制。

### 与本文档原方案的差异（实现时改了）

1. **实时层暂用轮询，未上 Channels/WebSocket**。第四节定的 daphne + WS 是**基础设施级改造**（换 ASGI 服务器、改 CMD、nginx 加 `/ws/`），风险与本次功能范围不匹配，故先按 12 秒增量轮询 + 手动刷新跑通全链路；前端已把「快照 + 聊天列表」两处渲染拆成独立函数（`seatSyncTargets`），后续接 WS 时只替换数据来源，页面逻辑不用动。
2. **大厅消息明确不进 workspace 快照**（第四节序列图未细化这点）。聊天无限增长，进快照会让每次 `/api/workspace` 越来越大，故改为独立分页接口 `GET /seats/chat`，快照里只留未读数。
3. **座位位置用「行-列」键而非座位号**（第三节 `Seat` 表）。地图可编辑 ⇒ 行列会变、座位号会重排，用坐标做键才不会被编辑动作打断。
4. **形象槽位把「下装」换成「椅背」**。坐姿下肢被桌子遮挡，下装调了没有反馈；换成椅背色后每个槽位都有可见效果。
5. **大厅只做公共频道**，未做 1v1 私聊。
