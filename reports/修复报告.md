**额外发现并修复**（QA 报告未列，修复过程中暴露）：

- **`setup_permissions.py` 的权限语义完全错误**：NetBox 的 `ObjectPermission.actions` 只能填 `view/add/change/delete`，原命令填的是 `view_hardware` 之类，后端拼出 `lab_manager.view_hardware_hardware` 这种永远匹配不到的权限 → **成员在任何受限表单里都选不到硬件**（借出功能对成员完全不可用）。已重写命令，并用 `python manage.py setup_permissions` 重建权限。
- **`validators.py` 中 `mime_type, _ = mimetypes.guess_type(...)` 覆盖了 gettext 的 `_`**：一旦校验器真正拒绝文件就抛 `TypeError: 'NoneType' object is not callable`。挂载校验器后立即暴露，已修。
- **`plugin_api_patterns` 定义了却从未挂载**（缺 `plugins-api` 命名空间）：导致 REST 序列化器无法生成 `url` 自链接。已在 `netbox/urls.py` 挂上 `/api/plugins/`。

## 六、对 QA 报告的两处更正（诚实记录）

1. **P0-5 的原始描述不准确**：报告中写"匿名可下载媒体文件（200）"，实测匿名请求是 **302 跳登录**（当时脚本用了默认跟随重定向的 `requests`，把登录页的 200 误判为文件内容）。真正的漏洞是**已登录的任意成员**可下载他人打卡照片/发票/附件——这一点已确认并修复。
2. **P1-9（移动端登录按钮被遮挡）的根因**是 Django Debug Toolbar 的覆盖层（`djdt-AlertsPanel`），属于开发期工具而非项目样式缺陷；关闭工具栏后消失。生产环境（`DEBUG=False`）本就不受影响。

## 七、未修复 / 建议后续处理

1. **LLM 调用无最大迭代数与总超时**：只加了单次工具耗时告警；真正的迭代上限需要按所用 LangChain 版本的 `create_agent` 参数确认后再加，避免写错参数导致智能体不可用。
2. **智能体 Markdown 渲染器的属性转义**：`renderMarkdown` 对 URL 分支未做完整引号转义（当前正则已排除引号，暂不可利用）。建议改为渲染后统一走白名单清洗。
3. **核心 REST API 仍缺失**：本实例裁剪掉了 `netbox/api/urls.py`（无 `dcim/ipam/core-api`）。导入页现在能打开，但表单里"从已有对象选择"的自动补全仍无数据源；若要完整导入功能，需要恢复核心 API 路由。
4. **`docs/` 目录**：其中 6 个文档描述的模型/页面从未存在（看板、二维码、Coze/Dify 网关等），`Dify配置信息.py` 还含真实密钥。建议整体归档，避免误导。
5. **`start.sh` 仍绑定 8000 端口**：本机 8000 被另一项目占用，当前服务跑在 8001；如需统一，改脚本里的端口即可。
6. **移动端智能体输入框仍在首屏之下**：390×844 下 `.agent-panel-footer` 位于 y=894–1047（视口高 844），需下滑约 200px 才能点到输入框。页面可正常纵向滚动（`scrollHeight > innerHeight`），因此**可达但不够顺手**。彻底解决要把 `.agent-shell` 的 `100dvh` 改为 `calc(100dvh - 顶栏高度)`，涉及主题 CSS 的固定定位体系，建议单独排期验证。
