# 实验室管理平台 — 界面可视化与排版分析报告 + 企业级优化方案

- **分析对象**：`http://localhost:8001/` 全部 19 个界面（列表 9 / 详情 5 / 仪表板 1 / 专用页 4）
- **方法**：Playwright 驱动真实浏览器，在 1440×900 与 390×844 两档视口逐页量化（滚动屏数、卡片与分区数、主内容起点、表格行数与列数、分页能力、横向溢出）；再用模板/视图源码定位结构性原因
- **原始数据**：`reports/qa/ui_metrics.json`、`ui_metrics2.json`；截图 `reports/qa/ui-*.png`
- **一句话结论**：**主题视觉已经成型（318 个设计令牌、统一像素风），但"信息架构 + 数据可见性 + 组件规范"这三层还是原型水平**——最典型的证据是：浏览记录页 **6.1 屏、104 行、0 个筛选器**，成员详情 **12 张卡片 / 10 个标题 / 移动端 3.2 屏**，打卡与浏览记录**根本没有分页**（硬编码 `[:200]` / `[:300]`）。

## 二、问题诊断（5 类结构性问题）

### 问题 1｜**数据可见性断裂**：4 个列表页没有分页，靠魔法数字截断

- **证据**：`views.py` 中 `checkins` → `records[:200]`、`member-open-records` → `records[:300]`、`notifications` → `[:50]`、`agent` → `conversations[:20]`；`checkin_list.html` / `member_open_record_list.html` 是手写 `<table>`，不走 NetBox 的 `ObjectListView`，因此**没有分页器、没有页大小、没有列配置**。
- **危害**：第 201 条打卡记录对用户**永久不存在且毫无提示**；浏览记录实测一次渲染 104 行、6.1 屏；审计/追溯场景直接失效（这是企业级审计的硬要求）。
- **根因**：这 4 个页面当初为了自定义表格样式绕开了框架的统一列表视图。

### 问题 2｜**首屏信息架构失焦**：仪表板把 14 张卡片一次性铺开

- **证据**：桌面 14 张卡片全在 902px 内（6 列 171px 迷你卡 + 4 张 545px 大卡）；移动端 10 张 KPI 卡纵向堆叠，**主内容起点被推到 y=1204px（1.4 屏以下）**。
- **危害**：桌面端信息密度过高（21px 高的小字卡看不清趋势）；移动端要滑两屏才看到"待审批/逾期"这类**需要行动**的信息——仪表板最重要的事被埋了。
- **根因**：卡片数量按"数据项"而非"决策优先级"排布，缺少 KPI 分层与移动端布局策略。

### 问题 3｜**详情页碎片化**：4–12 张卡片、6–10 个同级标题

- **证据**：成员详情 12 卡片 / 10 标题 / 2.1 屏（移动 3.2 屏）；任务详情 6 卡片 / 1.5 屏；打卡详情 2 卡片但单卡 1039px。
- **危害**：同一实体的信息被切成十几块，用户需要"扫读 + 拼接"；移动端首屏几乎全是标题与卡片边框；维护上每加一个字段就多一张卡。
- **根因**：缺少"详情页信息架构"（概要 / 关联 / 时间线 / 文件）与两栏布局规范。

### 问题 4｜**列表页可操作性不足**：宽表 + 零筛选 + 无行内操作

- **证据**：硬件表头 10 个（含勾选与操作列）、工具 9 个、借出 8 个；打卡记录与浏览记录 **0 筛选器、0 工具按钮**；分页/筛选只在做对了的 5 个页面存在。
- **危害**：数据一多就只能"翻页肉眼找"；无法按时间段、成员、状态过滤；无导出；窄屏全靠横向滚动。
- **根因**：手写列表页没有接入 NetBox 的 `FilterSet + Table + 表格配置` 体系，缺少统一的列表页规范。

### 问题 5｜**设计系统只有视觉层，没有组件层**

- **证据**：318 个 `--tp-*` 令牌（色/主题）说明视觉语言已统一；但 **449 个 `!important`**、8 个模板内联 `<script>`、1 个模板内联 `<style>` 说明缺少组件层与行为层规范；`lab_manager.css` 与 `terminal_pixel.css` 互相覆盖（如 `.calendar-day-checkin` 两处 `background` + `!important` 靠加载顺序决胜）。
- **危害**：新增页面靠"复制粘贴 + 试错"；改一处样式可能影响别处；无法沉淀设计资产，也无法做设计走查。
- **根因**：样式按"页面补丁"演进，未抽象出 `lm-*` 组件类与行为模块。

## 三、优化方案

> 每条按 **问题 → 方案 → 验收指标** 给出，验收指标都可用脚本复测（沿用 `reports/qa/ui_audit.js`）。

### 方案 A｜统一列表页规范（解决 P1 / P4）

1. **把所有列表页收敛到一套模式**：`ObjectListView + Table + FilterSet + FilterForm`，复用 NetBox 分页器（`?page=&per_page=`，页大小 25/50/100/250/500）。
   - 迁移对象：打卡记录、浏览记录、通知列表、成员列表、智能体会话。
2. **禁止静默截断**：任何"只显示最近 N 条"必须显式呈现，例如
   `显示最近 200 条 / 共 1,842 条 · [查看全部 →]`。
3. **列的三档视图**：`精简(4–5 列) / 标准 / 完整`，走 NetBox 的表格配置持久化到用户偏好；首列固定 + 粘性表头。
4. **补全列表页能力矩阵**：搜索框、时间范围、成员/状态筛选、导出 CSV、批量操作、空状态引导。
5. **移动端卡片化**：<768px 时宽表自动切成"卡片 + 关键字段 + 操作"，而不是横向滚动 10 列。

**验收**：任意列表页 `?page=2` 可访问；页脚显示"共 N 条 · 第 x/y 页"；每个列表页至少有 1 个搜索 + 1 个筛选 + 导出；窄屏无横向滚动。工作量：**1.5–2 天**（5 个页面，多数可复制现有 `object_list.html` 模式）。

### 方案 B｜仪表板重构为"决策优先"的信息层级（解决 P2）

推荐结构（桌面）：

```
┌─ KPI 行（4 张，高 ≤96px，含迷你趋势线）───────────────────┐
│ 硬件在用 3/5 ▲  任务进行中 2  ⏰今日打卡 3  ⚠️逾期 1      │
├─ 需要我处理（左 8 列，主区）───────┬─ 库存水位（右 4 列）─┤
│ 待审批硬件(2) / 逾期未还(1) /     │ 水位条 + 阈值色      │
│ 低库存(1) —— 每项带一键操作按钮    │ 采购建议入口         │
├─ 趋势（左 8 列，折线/柱状）────────┼─ 最近活动（右 4 列）─┤
│ 近 30 天任务完成率 / 借出量        │ 事件流（时间轴）     │
└────────────────────────────────────┴──────────────────────┘
```

- 移动端：KPI 改**横向 scroll-snap 条**（高 ≤96px），首屏必须露出"需要我处理"的前 2 条；把 14 张卡压缩为 4 KPI + 3 待办 + 1 水位 + 1 事件流。
- 次要指标（如各类占比）收进"更多指标"折叠区或 `/analytics/` 子页。

**验收**：桌面无滚动即可见 KPI + 待办；移动端首屏（844px）内出现待办 ≥2 条；仪表板总屏数 ≤2。工作量：**1 天**。

### 方案 C｜详情页两栏化 + 语义分区（解决 P3）

- ≥1200px：左 8 列（概要 + 时间线），右 4 列（元数据 + 操作 + 关联快捷入口）；<1200px 单栏堆叠。
- 语义分区数从 6–12 压到 **≤4**：`概要` / `关联对象(Tab: 任务·借出·打卡)` / `活动时间线` / `附件`。
- 卡片合并：同一语义的字段用 definition list（`<dl>` 两列）而不是一卡一项；卡片标题只保留 h2。
- 长内容（浏览记录、GPS 明细）改为 `Accordion` 或独立 Tab，默认折叠。

**验收**：成员详情 ≤2 屏且分区 ≤4；移动端 ≤3 屏；同级标题 ≤4 个。工作量：**1.5 天**（成员详情、任务详情、硬件详情、打卡详情）。

### 方案 D｜数据可视化升级（把"数字"变成"可判断的信息"）

| 场景 | 现状 | 建议 |
|---|---|---|
| 库存 | 纯数字 `quantity` 列 | **水位条**：`可用/总量`，低于 `minimum_stock` 变橙、=0 变红 |
| 任务进度 | 状态文字 | **看板视图**（拖拽改状态，超期卡红色描边）+ **甘特时间轴**（按执行人分组） |
| 考勤 | 表格 + 数字 | **年历热力图**（GitHub 贡献图风格），点某天钻取当日打卡 |
| 借出 | 列表 | **借用周期条**（借出→预计→实际归还三段时间轴） |
| 趋势 | 无 | 近 30 天折线：任务完成率、借出量、打卡人数 |
| 智能体 | 纯文本回复 | 回复中的表格/统计**内嵌图表卡片**（可导出） |

技术选型：优先 **轻量 SVG/CSS 图表**（<10KB，无依赖、与像素主题一致），复杂图表再引入单一图表库（如 ECharts 按需加载，`lm-charts.js` 统一封装）。

**验收**：库存页可用颜色一眼识别缺货；任务页可在看板内完成状态流转；考勤页 1 屏看完一年。工作量：**3–4 天**（看板 1.5 天、热力图 0.5 天、水位条 0.5 天、趋势图 1 天）。

### 方案 E｜设计系统分层（解决 P5）

**三层令牌**（在现有 318 个 `--tp-*` 之上收敛）：

| 层 | 示例 | 说明 |
|---|---|---|
| primitive | `--c-cyan-500:#00e5ff` `--space-2:8px` `--font-13:13px` | 色阶、间距、字号 |
| semantic | `--surface-1/2/3` `--border-subtle` `--text-primary/muted` `--accent` `--danger` `--warning` `--ok` | 按用途命名，主题切换只改这一层 |
| component | `--card-radius` `--table-row-h` `--btn-h` | 组件级 |

**组件类规范**（替代 `!important` 对抗）：`.lm-card` `.lm-card__header` `.lm-table` `.lm-toolbar` `.lm-kpi` `.lm-empty` `.lm-timeline` `.lm-badge`，全部基于令牌、零 `!important`。

**行为层**：8 处内联 `<script>` 收敛为 `lm-ui.js`（交互：抽屉/复制/确认/快捷键）与 `lm-charts.js`（图表），模板只留 `data-*`。

**验收**：`!important` 从 449 降到 ≤50；模板无内联 `<script>`（仅数据 JSON）；新增页面只组合 `lm-*` 类。工作量：**2–3 天**（可增量，不必一次重写）。

## 四、创意设计提案（企业级亮点）

1. **实验室指挥舱 / 值班大屏（Mission Control）**
   单屏 4 分区：KPI 条 · 待办队列 · 库存水位 · 实时事件流。提供"投屏模式"：暗色高对比、字号放大 1.5 倍、30 秒自动刷新、Escape 退出。契合电赛/实验室现场值守场景，也是最有"企业级观感"的一屏。

2. **AI 副驾驶常驻侧栏（Context-aware Copilot）**
   任意页面右上角唤起，自动携带当前上下文（"你正在看硬件 #3 Test MCU Board"），提供上下文相关动作：*生成借用单 / 写采购建议 / 总结该成员近期活动 / 找出相似任务*。把现有智能体从"独立页面"升级为"全站副驾驶"——这是最能体现差异化的设计。

3. **命令面板（Ctrl / ⌘ + K）**
   聚合"跳转 + 操作 + 搜索"：输入"借 3 号开发板给胡涵"直接弹出预填的借出表单；输入"待审批"直接跳到筛选后的硬件列表。落地成本低（一个模态 + 一个 JSON 索引），体验跃升明显。

4. **库存水位 + 阈值色阶**
   把 `quantity / minimum_stock` 渲染成水位条（绿→橙→红），鼠标悬停显示"在借 N · 可用 M · 阈值 K"。低库存项在列表顶部用一条"采购待办"横幅汇总。

5. **考勤热力图 + 异常提示**
   年历热力图（深浅 = 当日打卡次数），叠加"连续未打卡 ≥3 天"的标记；点击某天右侧抽屉展示当日打卡详情与照片缩略图。

6. **像素终端彩蛋：`>` 命令行条**
   在主题里已经有的"终端"气质上，加一个可选的底部命令条（默认收起），支持 `?` 帮助、`/hw 开发板`、`/task done 12` 等极简操作，强化品牌一致性（对实验室用户友好，且不影响普通用户）。

**P1（部分完成）**
6. 表格密度切换（紧凑/舒适，localStorage 持久化）+ 框架表格粘性表头 + 首列固定。

**P2（全部完成）**
