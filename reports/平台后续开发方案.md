# 具身智能实验室管理平台 · 后续开发完整方案

> 基于《后续开发.md》12 项需求 + 结合现有架构（lab-platform Django + SPA + RBAC 权限系统）的落地设计。
> 每个需求给出：功能说明、后端落位（模型/接口）、前端落位、权限点、依赖关系与优先级。

---

## 总览：分期与依赖

| 阶段 | 内容 | 理由 |
|------|------|------|
| **P0 基础设施先行** | ②公告 + ⑦改密码 + 小组模型 | 改动小、无外部依赖、其余需求复用（分组是①⑨的地基；公告是⑤⑧的载体） |
| **P1 核心业务深化** | ①成员详情/分组管理 + ⑨任务按成员/小组 + ⑫任务详情 | 围绕"人-组-任务"主线，用户最常用 |
| **P2 激励与提醒** | ⑪积分制度 + ⑩开赛倒计时 + ⑧邮件提醒 | 依赖任务/打卡/比赛的既有数据流 |
| **P3 智能化** | ④智能体改造（操作+个人记忆） + ⑤跨平台接口 + ③实时跟进 | 技术复杂度高，放后期 |
| **P4 体验打磨** | ⑥动效 + 我补充的增强项 | 收尾优化 |

**权限体系约定**：每个新功能按现有 RBAC 增加权限点（`page:*` 控制菜单与页面、`action:*` 控制操作按键/后端接口），默认种子给三内置角色，superadmin 自动全量。下表不再逐条重复此约定，只列出关键权限点。

## ① 成员详情页 + 分组管理

### 功能
- 成员列表点"详情"跳转到**独立详情页**（替代当前 modal）：基本信息、负责/参与的任务、借用历史、打卡统计、积分、操作记录——含可视化图表
- 新增**分组管理页**：创建/编辑小组（组名、人数上限、队长、成员列表）；成员归属小组，详情页显示

### 后端
- **模型**（accounts）：
  - `LabGroup`：`id=G-001`、name、leader(FK User)、capacity、note、created
  - `MemberProfile.group_fk = FK(LabGroup, null=True, on_delete=SET_NULL, related_name='members')`（保留现有 `group` 文本字段做展示，逐步迁移）
- **接口**：
  - `GET /members/<mid>/detail`：聚合个人全量数据（任务/借用/打卡/日志）
  - `groups` CRUD：`POST /groups`、`POST /groups/<gid>/update`、`POST /groups/<gid>/delete`、`POST /groups/<gid>/members`（增删成员）
- workspace 快照增加 `groups` 键

### 前端
- `src/members.js`（新文件）：`memberDetailPage`（独立页，hash 路由 `#member/<id>`）、`groupsPage`（小组卡片网格 + 编辑）
- 路由改造：`app.js` 的 `go()` 支持 `#member/m3` 这类带参数路由
- 图表：纯 CSS/SVG 实现任务完成数柱状、打卡近 30 天热力条（不引第三方库，保持无依赖风格）

### 权限点
`page:groups`、`action:group.manage`（建/改/删组）、`action:group.members`（调配组员）、`page:member.detail`

### 风险
- `group` 文本字段与 `group_fk` 并存期需同步写入，避免数据漂移

## ② 公告系统

### 功能
- 公告管理页：发布/编辑/置顶/下架；标题、内容（Markdown）、发布时间、发布人、接收范围（全员/指定小组/指定成员）
- 工作台顶部横幅显示最新置顶公告；未读角标

### 后端
- **模型**（启用现有 `apps/notify` 空壳，注册进 INSTALLED_APPS）：
  - `Announcement`：id、title、content、author(FK)、pinned(bool)、scope_type(all/group/members)、scope_json、active(bool)、created、updated
  - `AnnouncementRead`：announcement FK + user FK + read_at（未读统计）
- **接口**：`announcements` CRUD + `POST /announcements/<id>/read`（标记已读）
- workspace 快照：`announcements`（当前用户可见的）+ `unread_announcements` 计数

### 前端
- `src/notify.js`：`announcementsPage`（卡片流：置顶在上、未读标记）、发布/编辑表单（textarea + 范围选择器）
- 工作台 `dashboard` 顶部插入公告横幅条；顶栏铃铛角标改为"未读公告+待办"合计

### 权限点
`page:announcements`、`action:announcement.create`（发布）、`action:announcement.update`（改/下架）——默认仅 teacher/manager 有

## ③ 实时跟进（行业动态）

### 功能
- 新页面"实时动态"：聚合 AI/具身智能领域新闻，时间线卡片流
- 来源可选：RSS 抓取（实验室指定源）或 LLM 每日摘要生成

### 后端
- **模型**（notify app）：`NewsItem`：id、source、title、url、summary、published_at、fetch_source(manual/rss/llm)
- **采集**：`manage.py` 命令 `fetch_news`（读配置的 RSS 源，requests 拉取解析，去重入库）；管理员可手动录入
- LLM 摘要：调现有 `apps/agent/service.py` 的 DeepSeek 配置做一句话摘要
- **接口**：`GET /news`（列表，workspace 快照外单独分页）、`POST /news`（手动录入）

### 前端
- `src/news.js`：时间线卡片页，来源徽章 + 摘要 + 原文链接（新窗口）

### 权限点
`page:news`、`action:news.manage`（录入/删除）

### 风险
- 服务器 RSS 抓取依赖外网可达；设失败静默+手动录入兜底

## ④ 智能体升级：可操作 + 个人记忆

### 功能
- 智能体从"只读问答"升级为"**可操作**"：用户说"帮我建一个任务：调试电机"→ AI 直接调任务创建接口
- 关键约束：**AI 只能执行当前用户拥有的权限**（接入 RBAC）
- 每个用户独立上下文记忆与历史（已有 Conversation per-user，需增强为长期记忆）

### 后端（改 apps/agent）
- **工具层改造**：现有 5 个只读工具 + 新增写工具（`create_task`、`apply_loan`、`apply_leave`、`query_competitions`、`check_today` 打卡状态等）
- **权限门控**：每个工具声明所需权限点（如 `create_task` → `action:task.create`），执行前 `require(user, key)`，无权限的工具**不出现在该用户的 TOOLSPEC**（从 prompt 层就隔离，而非事后拦截）
- **个人记忆**：`UserMemory` 模型（user FK + key + value + updated）：AI 可读写"记住我的方向是 STM32"这类偏好；对话历史已有
- **接口**：`POST /agent/chat` 不变（内部增强）；`GET/POST /agent/memory`（查看/清空自己的记忆）

### 前端
- `agent.js`：AI 回复中渲染"已执行操作"卡片（如"✅ 已创建任务 TASK-003"），带跳转链接；操作类请求前端二次确认弹窗（防误操作）

### 权限点
复用现有 action 权限点（工具与权限点一一映射）；新增 `action:agent.operate`（是否允许 AI 代操作，默认仅 staff）

### 风险
- LLM function calling 的写操作必须二次确认 + 全程写操作日志（复用 OperationLog）
- 成本控制：上下文窗口截断策略（近 20 条 + 记忆摘要）

## ⑤ 跨平台数据接口（API Token）

### 功能
- 给外部 AI（Trae 等）提供只读数据接口：凭 API Key 查询硬件清单等
- 安全：令牌认证、只读、可调可撤、全程审计

### 后端
- **模型**（accounts）：`ApiToken`：id、name、user(FK)、token_hash（只存哈希）、scopes（JSON 数组，如 `["read:assets","read:loans"]`）、active、last_used_at、expires_at、created
- **认证**：`apps/common/auth.py` 新增 `TokenAuthentication`（读 `Authorization: Bearer <token>`，校验哈希+active+过期）
- **接口**：`/openapi/assets`、`/openapi/loans` 等只读端点（按 scope 过滤）；管理接口 `POST /tokens`、`POST /tokens/<id>/revoke`
- 每次调用写 `OperationLog`（标注 token 名称）

### 前端
- 个人中心新增"API 令牌"区块：创建（一次性明文展示）、列表、吊销

### 权限点
`action:token.manage`（创建/吊销自己的令牌）

### 风险
- token 明文只在创建时返回一次；哈希存储；默认 90 天过期
- 建议 scope 只放只读，写操作不开

## ⑥ 界面动效

### 功能
- 页面切换/数据加载时的克制动效：数字 0→N 滚动计数、卡片依次浮现、进度条生长

### 前端
- `src/animations.js`（新文件）：`IntersectionObserver` 驱动的浮现动画；`requestAnimationFrame` 数字滚动；仅对 `.stat-value`、`.panel`、`.member-card` 生效
- 尊重 `prefers-reduced-motion`（用户系统级减动效时全部跳过）
- 时长 ≤0.6s、位移 ≤24px、单次播放不循环（遵守项目动效克制约定）

### 风险
- 低性能设备：`matchMedia('(prefers-reduced-motion)')` + 元素数量阈值（>50 个卡片时降级为无动画）

## ⑦ 修改密码 + 管理员重置他人密码

### 功能
- 个人中心"修改密码"：旧密码验证 + 新密码规则校验
- 管理员在成员详情可"重置密码"：生成随机密码一次性展示，强制用户下次登录后修改

### 后端
- **接口**：`POST /members/me/password`（旧密码+新密码，Django `check_password` 验证）；`POST /members/<mid>/reset-password`（仅 staff，返回一次性随机密码）
- `MemberProfile.must_change_password = BooleanField(default=False)`：重置后置 True，登录后强制跳改密

### 前端
- `profile.js` 个人中心加"安全"卡片区；成员详情页加"重置密码"按钮（`action:member.reset_password`）
- 登录后检查 `must_change_password`，为 true 则弹强制改密 modal（不可关闭）

### 权限点
`action:member.reset_password`（默认 teacher/manager）

## ⑧ 邮件提醒

### 功能
- 规则化邮件：任务临期（截止前 N 小时）、借用逾期、比赛报名截止前 N 天、请假审批结果通知
- 规则在管理界面可视化配置（开关、提前量、接收人范围、邮件模板）

### 后端
- **配置**：`EmailConfig`（单例模型）：smtp_host/port/user/password(加密存储)/from_addr/enabled
- **规则**：`EmailRule` 模型：key(task_due/loan_overdue/competition_deadline/leave_result/custom)、enabled、hours_before、scope、subject_tpl、body_tpl（支持 `{name} {title} {due}` 占位符）
- **发送引擎**：`manage.py send_reminders` 命令（cron 每 30 分钟跑）：扫描各业务表 → 匹配规则 → `django.core.mail` 发信 → 记录 `EmailLog`（防重发：同一对象同一规则一天只发一次）
- **接口**：`GET/POST /email/config`（SMTP 配置+测试发信）、`email/rules` CRUD、`GET /email/logs`

### 前端
- `src/email.js`：邮件设置页（SMTP 表单 + 发送测试按钮 + 规则卡片列表：每项开关+提前量+模板编辑）

### 权限点
`page:email`、`action:email.manage`（仅 superadmin/teacher）

### 依赖
- 成员需有邮箱：`MemberProfile.contact` 目前放联系方式——**新增独立 `email` 字段**（或在资料页拆出）
- 服务器需放行 SMTP 端口（25/465/587，阿里云默认封 25，用 465 SSL）

### 风险
- 阿里云 ECS 默认禁 25 端口 → 必须走 465/SSL；密码字段加密（Django signing）不落明文

## ⑪ 积分制度 + 排行榜 + 配置

### 功能
- 积分来源：任务完成评分（管理员打 1-5 星，星级 × 任务基础分）、每日打卡、连续打卡加成、借用按时归还
- 成员详情页显示积分曲线；新页面"积分排行榜"（周/月/总榜）
- 管理界面配置各项分值

### 后端
- **模型**：
  - `PointRule`：key(task_complete/checkin_daily/checkin_streak/loan_on_time/custom)、points(int)、enabled
  - `PointRecord`：user FK、rule key、points、ref_type/ref_id（关联任务/打卡记录）、reason、created
  - `Task.score`：IntegerField null（1-5 星评分，完成时由管理员打）
- **积分引擎**：`apps/points/`（新 app）：`award(user, rule_key, ref)` 统一入口，写 PointRecord + 触发 OperationLog
- 挂载点：任务转 done 且被打分时、打卡创建时、借用验收无损坏时
- **接口**：`GET /points/rules` + `POST /points/rules`（配置）、`GET /points/leaderboard?period=week|month|all`、`POST /tasks/<tid>/score`（评分）
- workspace 快照：`points_total`（本人）、`leaderboard_top10`

### 前端
- `src/points.js`：排行榜页（前三名放大卡片 + 其余列表 + 周期切换）
- 成员详情页加积分卡（总分 + 近 30 天趋势条）
- 任务完成流转时弹评分组件（5 星，管理员可见）
- 邮件设置页同区或独立"积分规则"配置卡片

### 权限点
`page:leaderboard`（全员可看）、`action:task.score`（评分，默认 teacher/manager）、`action:points.rules`（规则配置，默认 teacher/superadmin）

### 依赖
⑨ 的任务流转；① 的详情页

## 补充建议（便于实验室管理与监管，文档外新增）

| # | 功能 | 价值 | 复杂度 |
|---|------|------|--------|
| A | **数据导出**（成员/借用/任务/打卡 → CSV） | 期末汇报、审计留档的硬需求 | 低 |
| B | **设备盘点模式**（stocktake：生成盘点清单 → 现场扫码/勾选核对 → 差异报告） | 学期初/末资产管理刚需 | 中 |
| C | **登录日志与安全**（记录登录 IP/时间/设备，异常登录告警） | 监管 + 配合⑤的令牌审计 | 低 |
| D | **周报自动生成**（每周一自动汇总：本周打卡/任务完成/借用动态 → 站内公告或邮件） | 指导老师的监管视角 | 中 |
| E | **借用信用分**（逾期扣分，信用过低限制借用） | 与⑪积分联动，治逾期 | 低 |
| F | **维修 SLA 看板**（维修中模块的平均修复时长、超期预警） | 资产健康度监管 | 低 |
| G | **操作日志增强**（按模块/操作人筛选 + 导出，复用现有 OperationLog） | 已有的日志页只需加筛选 | 极低 |

**推荐纳入排期**：A（数据导出）和 G（日志筛选）投入最小收益最直接，建议插入 P0；C 登录日志随⑤令牌一起做。

## 全局技术约定

1. **RBAC 集成**：每个新页面在 `rbac_defs.py` 注册 `page:*` 权限点 + `PERMISSION_MENU_GROUPS` 菜单分组，在权限矩阵中可勾选；写操作注册 `action:*` 并在后端视图 `require()`
2. **模型规范**：新模型统一 `id = next_code(Model, '前缀')` 短码；用户对外 ID 用 `m{user.pk}`
3. **快照同步**：新增数据类目必须实现 `workspace_slice(profile, staff)` 并在 `build_workspace` 注册 + 同步 API.md
4. **部署约束**：2GB 服务器 gunicorn 保持 1 worker；邮件/新闻等定时任务用宿主机 cron + `docker exec` 执行 manage.py 命令，不引入 celery
5. **每阶段交付即部署**：本地测试 → `npm test` → scp 同步 → docker build → 冒烟

## 里程碑验收点

- **P0 完成**：能改密码、能发公告、有小组模型
- **P1 完成**：成员详情页可看全维度数据，任务可按人/组浏览，任务有详情页可传材料
- **P2 完成**：积分排行榜上线、比赛倒计时可见、临期邮件能发出
- **P3 完成**：AI 能按用户权限代操作、外部可用 Token 只读调取、动态页可看
- **P4 完成**：动效克制上线、导出/盘点/日志增强就绪
